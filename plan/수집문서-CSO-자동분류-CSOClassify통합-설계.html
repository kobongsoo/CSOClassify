통합 구현 설계 · Auto-Classification

수집 문서 C·S·O 자동 분류
— CSOClassify 임베딩 통합 설계

CSOClassify가 이미 뽑아 놓은 추출 텍스트와 임베딩 벡터를 그대로 재료로 삼아, 수집된 문서 더미를 기밀·민감·공개(C/S/O)로 자동 분류한다 — 별도 스캔 없이, 인덱싱과 한 흐름으로.

문서유형 통합 구현설계 기반 A 출처기반 2단계 자동등급화 기반 B CSOClassify(추출→임베딩) 등급체계 C / S / O 작성일 2026-08-12
한 줄 요약

CSOClassify 파이프라인의 부산물 두 개(정제 텍스트 · 벡터)를 분류기의 입력으로 재사용한다. 텍스트엔 규칙 스캔, 벡터엔 라벨 전파를 걸어 문서마다 C/S/O 후보를 만들고, max(경로·규칙·전파) 로 보수적 확정한다. 임베딩은 상향에만 쓰고(하향 금지), 애매한 것은 검토 큐로. 확정 등급은 그대로 RAG 인덱싱의 관문이 된다.

01

왜 이 조합인가 — 두 자산의 결합

기존 출처기반 2단계 등급화 설계는 이미 §2.5에서 "초기 코퍼스는 CSOClassify 인덱싱 단계 안에 분류를 인라인하라" 고 예고했다. 이 문서는 그 예고를 실제 CSOClassify 코드 인터페이스에 맞춰 구현 설계로 확정한다.

핵심 통찰은 하나다 — 분류기가 필요로 하는 두 재료를 CSOClassify가 이미 한 번의 처리로 둘 다 생산한다는 점이다. 문서를 다시 열 필요가 없다.

Korean

03

분류기는 CSOClassify의 기존 결과 dict 를 그대로 소비한다. 파이프라인 결과는 이미 아래 형태로 나온다(pipeline.process_file()).

# process_file() 은 이미 내부에 'text' 를 들고 있다(clean 단계 결과) → 결과 dict 에 실어 주기만.

    ... core ...,                       # dim/chunks/vector|vectors (기존)

}

# 제안 ② 새 서브커맨드/모드: classify (내부에서 process_file 재사용)
csoclassify.exe classify -dir D:\collected --glob "*.*" \
    --seed seeds.jsonl --rules cso_rules.yaml \
    --format jsonl --out grades.jsonl
원칙

분류는 새 서브패키지 csoclassify/classify/ 로 격리한다. 추출·임베딩·데몬 코어는 순수하게 유지하고, 분류기는 그 소비자로만 존재한다 → 엔진과 정책의 분리(테스트·감사 용이).

05

Signal A — 규칙 스캔 (추출 텍스트 기반)

CSOClassify가 뽑은 정제 텍스트에 계층적 규칙을 걸어 내용 위험도 와 rule_grade 를 산출한다. 사람이 아닌 기계가 패턴만 확인한다.

계층방법탐지 예→ 등급
L1정규식 패턴 매칭주민번호·카드번호·계좌·여권번호C / S
L2키워드/기밀 사전"대외비", "인사평가", "M&A", 프로젝트 코드명C / S

L4(선택) 분류 ML / 임베딩계약서·재무제표·설계도 유형 자동 인식유형→정책
Privacy

탐지된 실제 값(주민번호 원문 등)은 저장하지 않는다. "주민번호 패턴 12건 검출"처럼 메타 결과만 근거로 남긴다. CSOClassify의 --save-text 는 분류 후 기본 자동삭제 를 유지(민감 텍스트 잔존 방지).

06

Signal B — 임베딩 라벨 전파 (핵심 엔진)

수집 코퍼스는 대부분 출처 흔적이 약하다. 여기서 CSOClassify 벡터가 주력이 된다 — 이미 등급이 붙은 seed 문서의 라벨을, 벡터 공간에서 가까운 미분류 문서로 전파한다.

Seed
라벨 씨앗

Signal C/A(경로·규칙)에서 고신뢰 로 등급이 붙은 문서 + 등급/주제별 소량의 사람 검증 앵커셋.

Propagate
벡터 전파

미분류 문서 → 가까운 seed 이웃의 등급을 k-NN·센트로이드 로 부여. 유사도 임계 미만은 검토 큐로.

Dedup
중복 즉시 상속

코사인 ≈ 1.0 near-duplicate(같은 계약서가 여러 폴더에 복사)는 사본 전체가 한 번에 상속 → 대량 정리.

전파 알고리즘 (요지)

def propagate(vec, seeds, k=15, tau_hi=0.82, tau_lo=0.62):
    nn = top_k_cosine(vec, seeds, k)           # CSOClassify 벡터로 k 최근접 seed
    if nn[0].sim >= 0.985:                    # near-duplicate → 사본 상속
        return nn[0].grade, nn[0].sim, "dup_inherit"
    grade, conf = weighted_vote(nn)            # 유사도 가중 다수결(+등급 사전확률)
    if conf < tau_lo:                         # 이웃이 흩어짐 → 판단 보류
        return None, conf, "review_queue"
    return grade, conf, "knn_vote"          # 후보 등급(상향 전용)
주의

임베딩은 주제·의미를 잡지 민감도 자체를 보증하지 못한다(공개 안내문과 기밀 급여대장이 이웃일 수 있다). 전파 결과는 "후보 등급" 일 뿐 — 상향·확인에만 쓰고 임베딩만으로 하향 금지. 강한 ACL·기밀사전 히트는 전파보다 규칙을 우선한다.

07

등급 융합 결정 — 보수적 최댓값 + fail-safe

네 신호가 각자 후보를 낸다. 충돌 시 항상 높은 등급 우선(C > S > O). 근거가 약하면 안전측 기본값으로 떨어뜨린다.

최종등급 = 등급최댓값( path_grade, rule_grade, name_grade, embed_grade )   # C > S > O
def fuse(sig):
    cands = [sig.path, sig.rule, sig.name, sig.embed]      # 각 신호의 후보(없으면 제외)
    strong = sig.acl_restricted or sig.rule_confidential   # 강한 규칙/ACL 신호

    if strong:
        return max_grade(cands), "rule_or_acl_wins"   # 규칙/ACL 우선
    if any_present(cands):
        return max_grade(cands), "max_fusion"       # 임베딩은 상향에만 기여

    # 아무 신호도 확정 못 함 → fail-safe
    return ("C" if sig.acl_restricted else "S"), "failsafe_default"
경로/ACL규칙(텍스트)전파(벡터)최종의미
O 공개 폴더주민번호 대량급여대장 이웃C공개 위치에 숨은 기밀을 텍스트가 잡아냄 ✓
C 기밀 ACL특이사항 없음공개문서 이웃C임베딩이 낮게 봐도 하향 금지(ACL 우선)
불명특이사항 없음계약서 군집(고신뢰)S전파로 상향 후보, 검토 대기
불명특이사항 없음이웃 흩어짐(저신뢰)S → 검토 큐Fail-safe: 모르면 중간등급
원칙

내용·전파로 등급을 올릴 순 있어도 함부로 내리지 않는다. 하향은 승인 워크플로를 경유한다. 근거가 약한 애매지대는 검토 큐 로 — 이 큐가 작을수록 좋은 설계.

08

신규 모듈 · 데이터 스키마

CSOClassify 코어를 소비하는 csoclassify/classify/ 서브패키지를 신설한다. 엔진은 순수하게 두고, 정책(룰셋·seed·임계값)은 외부 파일 로 주입한다.

src/csoclassify/classify/
  signals.py     경로/ACL · 파일명 · 규칙(텍스트) 신호 추출
  rules.py       L1~L4 규칙 스캔(정규식·기밀사전·구조밀도)  # 원문 미저장
  propagate.py   seed 로드 · k-NN/centroid 라벨 전파 · near-dup 상속
  fuse.py        신호 융합(max + fail-safe), 검토 큐 라우팅
  store.py       분류 레코드 출력(jsonl) · 감사 로그
  cli.py         classify 서브커맨드(내부에서 pipeline.process_file 재사용)
resources/policy/
  cso_rules.yaml   기밀사전·정규식·경로→등급 매핑(운영자 관리)
  seeds.jsonl      {file, grade, vector} 라벨 씨앗

감사

RAG 인덱싱 연동 — 등급을 관문으로

분류 레코드의 vector 는 CSOClassify가 만든 그 벡터다 — 재임베딩 없이 그대로 인덱싱 한다. 등급은 청크 메타로 태깅되어, 챗봇 답변 시 사용자 권한에 따라 필터링된다.

C
기밀
Classified
  • 벡터DB 인덱싱 제외 또는 접근통제 기밀 인덱스
  • 외부 생성형 AI 완전 차단
  • 사내 온프레미스 AI는 격리망 내에서만, 감사 로그 필수
S
민감
Sensitive
  • 인덱싱 시 PII 마스킹 후 저장
  • 사내 RAG 허용(마스킹 적용)
  • 외부 AI는 승인 후 제한적
O
공개
Open
  • 벡터DB 자유 인덱싱
  • 사내 RAG 자유 사용
  • 생성형 AI 자유 활용

인덱싱 게이트 규칙

def index_gate(rec):
    if rec.grade == "C":
        return skip_or_secure_index(rec)      # 제외 또는 기밀 인덱스
    chunk_meta = {"grade": rec.grade, "rule_version": rec.rule_version}
    if rec.grade == "S":
        rec = mask_pii(rec)                    # 마스킹 후 인덱싱
    return index(rec.vector, chunk_meta)      # 등급 태그를 청크마다 부착
연동

사내 RAG 챗봇 인프라의 인덱싱 API(index_document(s))에 등급 메타 를 실어 호출한다. 챗봇은 검색 시 사용자 권한과 청크 등급을 대조해 C 청크를 자동 배제한다.

10

도입 로드맵

PHASE 0
정책 정의 · CSOClassify 스키마 확장

cso_rules.yaml(기밀사전·경로매핑) 작성, process_file 에 emit_text 옵션 추가.

PHASE 1
Signal A·C·D 가동(규칙·경로·파일명)

추출 텍스트 규칙 스캔 + 경로/ACL로 seed 확보 → 고신뢰 문서 1차 등급화.

PHASE 2
Signal B 라벨 전파

seed 벡터로 미분류 대량 상속(near-dup 우선), 저신뢰는 검토 큐. 수집 코퍼스 주 커버.

PHASE 3
융합·검토 큐·감사 로그

max+fail-safe 확정, 검토 큐 UI, 판정 근거 감사 기록 → 정확도 샘플링 검수.

PHASE 4
RAG 인덱싱 게이트 연동

등급 메타 태깅 인덱싱, 등급별 정책 자동화 → 실사용.

PHASE 5
정상상태 전환

신규 유입은 출처기반 fast-path 복원, 룰셋·seed 재전파 루프 정착.
