띄어쓰기 끝말 목록(DOC_SUFFIXES) 사전 이관

코드 두 곳(Python·Rust)에 박혀 있는 끝말 목록을 유의어 core 사전의 suffixes: 칸으로 옮긴다. 끝말 하나 추가에 코드 수정·재빌드가 필요 없고, 회사별 사전(local)에서 더할 수 있게 한다. 2026-09-15 구현 완료

1배경 — 끝말 목록이 하는 일

업무분류 규칙은 "분류 불러오기"(화면) 또는 --sync-doc-rule(CLI) 때 분류 이름에서 자동으로 만들어진다. 이때 이름 하나에서 띄어쓰기만 다른 표기를 먼저 만든다. 엔진은 글자가 똑같아야 찾기 때문이다.

분류 이름 "요구사항정의서" ① 이름 그대로 → 요구사항정의서 ② 끝말 앞에서 한 번 띄움 → 요구사항 정의서 ← 끝말 목록에 "정의서"가 있어서 ③ (파일명 칸만) 공백 → _ / - → 요구사항_정의서, 요구사항-정의서

②의 "끝말"이 DOC_SUFFIXES다. 목록에 없는 끝말로 끝나는 이름은 ②가 건너뛰어지고, ②가 없으니 ③도 만들어지지 않는다.

효과가 나는 자리

엔진의 제목·앞부분·파일명 검사는 이미 문서와 규칙 단어 양쪽의 공백을 지우고 비교한다 (자간 벌린 제목 대응). 그래서 끝말 목록이 실제로 결과를 바꾸는 곳은 두 곳뿐이다.

검사 자리공백 지우고 비교끝말 목록이 없을 때 놓치는 것
제목(첫 줄)예없음
앞부분(head_chars)예없음
파일명예 (공백만, _·- 는 그대로)설치_메뉴얼_v2.pdf 같은 구분자 표기
본문 전체아니요본문의 띄어 쓴 표기(보조 증거 0.15라 단독 영향 작음)

2문제

  1. 같은 목록이 두 곳에 있다. src/csoclassify/classify/docvocab.py 의 튜플(43개)과 Rust/src/docvocab.rs 의 [&str; 42] + DOC_SUFFIX_LAST. 한쪽만 고치면 화면과 엔진이 다른 규칙을 만든다. 골든 테스트가 잡아 주지만, 정답표를 손으로 다시 뽑아야 한다.
  2. 끝말 하나에 코드 수정·테스트·재빌드가 든다. 2026-09-15 메뉴얼 추가(PR #6)가 실제로 그랬다 — 두 파일 수정, 배열 길이 변경, 실행파일 재빌드.
  3. 고객사가 자기 끝말을 넣을 방법이 없다. 그 회사만 쓰는 문서 끝말(예: "품의안", "시행문")은 사전의 aliases 로 이름마다 적는 수밖에 없다.

3목표와 하지 않는 것

목표

  • 끝말 목록의 원본을 core 사전으로 옮긴다. 업종·local 사전에서 더할 수 있다.
  • 현재 사전·분류체계에서 규칙 생성 결과가 한 글자도 바뀌지 않는다(골든 테스트 그대로 통과).
  • 앞뒤 호환: 옛 엔진 + 새 사전, 새 엔진 + 옛 사전 모두 지금과 같은 결과.
  • Python·Rust 가 같은 규칙으로 읽는다.

하지 않는 것

  • 꼬리말 규칙(tails) 이름을 끝말로 자동 겸용 — 결과가 달라지므로 별도 단계(15장).
  • local 에서 끝말 빼기 — 다른 칸과 같이 더하기만 된다.
  • 화면에서 끝말을 편집하는 기능 — 사전은 지금도 파일로만 고친다(화면이 사전을 다시 쓰는 코드는 없다, 확인함).

4결정 요약

항목결정이유
위치기존 doc_synonyms.<겹>.yaml 안 suffixes: 칸 새 파일(doc_suffixes.yaml)은 로더·겹 합치기·배포 목록·초기화 목록·빌드 스크립트를 새로 만들어야 한다. 사전 안 칸은 이미 있는 core→업종→local 겹과 사본 경로를 그대로 쓴다.
모양문자열 목록 (다른 칸은 map)끝말에는 딸린 값이 없다.
합치기기준 목록 + 업종 + local 합집합다른 칸과 같은 "더하기만" 규약.
기준 목록core 에 suffixes 가 있으면 그것, 없으면 코드 내장 목록 옛 core + 새 local 조합에서 내장 43개가 사라지지 않게(6장 ②).
순서합친 뒤 긴 것부터 안정 정렬tails·heads 와 같은 처리. 관리자가 순서를 몰라도 된다.
검증2글자 미만·공백 포함·문자열 아님 → 버림. 중복 제거"서" 한 글자가 들어가면 모든 "~서" 이름이 이상하게 끊긴다.
코드 내장 목록남긴다(사전이 없을 때 대비). 사전과 같은지 테스트로 묶는다 사전은 "없어도 되는 파일"이 원칙.

5사전 모양

# ------------------------------------------------------------------

#    "요구사항정의서" → "요구사항 정의서" (파일명 칸은 "요구사항_정의서"·"요구사항-정의서" 도)

6읽기·합치기 규칙

load_synonyms(doc_rule.yaml) 겹 순서: core → 업종(뒤에 적은 것부터) → local ← 지금과 같다 ① 겹마다 suffixes 읽기 목록이 아니면(map·문자열) → 그 겹의 suffixes 는 없는 것으로 본다 항목마다: 문자열로 → 앞뒤 공백 제거 비었거나 · 안에 공백이 있거나 · 2글자 미만 → 버린다 ② 기준 목록 정하기 core 겹에 쓸 수 있는 항목이 1개 이상 → core 의 목록 그 밖(core 없음·칸 없음·빈 목록) → 코드 내장 DOC_SUFFIXES ③ 기준 목록 + 업종 겹들 + local 겹을 이어 붙이고 중복 제거(처음 나온 자리 유지) ④ 긴 것부터 안정 정렬 → syn["suffixes"] 사전이 한 겹도 없으면 load_synonyms 는 지금처럼 {} → 띄어쓰기 표기는 내장 목록
②에서 "local 만 적힌 경우"를 기준 목록으로 보지 않는 이유
고객사에 옛 core(칸 없음)가 깔린 채 local 에 suffixes: [품의안] 만 적으면, "한 겹이라도 적었으면 그것이 전부" 규칙에서는 끝말이 품의안 하나가 되어 내장 43개가 조용히 사라진다. 오류도 안 나고 규칙만 나빠지므로, 기준 목록은 core 에서만 받는다.
순서를 길이로만 세워도 되는 이유
두 끝말이 같은 이름에 동시에 걸리려면 한쪽이 다른 쪽의 끝토막이어야 하고, 그러면 반드시 더 길다. 길이가 같은 두 끝말은 한 이름에 동시에 걸릴 수 없다. _order_longest_first 와 같은 논리다.
빈 목록 suffixes: [] 은 "끄기"가 아니다. ②에서 내장 목록으로 돌아간다. 끝말 기능 자체를 끄는 설정은 두지 않는다 — 끌 이유가 없고, 실수로 꺼지면 파일명 구분자 표기가 통째로 사라진다.

자리변경
DOC_SUFFIXES그대로 둔다. 주석을 "사전에 suffixes 가 없을 때 쓰는 기본값"으로 고친다.

load_synonyms겹 루프에서 core 겹 목록과 나머지 겹 목록을 따로 모은 뒤 6장 ②③④. 결과에 merged["suffixes"].
_spacing_forms(word)_spacing_forms(word, suffixes=None) — suffixes or DOC_SUFFIXES 를 훑는다.
rule_vocab · title_variants_spacing_forms(base, (syn or {}).get("suffixes")) 로 부른다.
#------------------------------------------------------------------
# 끝말 목록 한 겹 정리하기
#=> 사람이 적는 칸이라 모양이 틀릴 수 있다. 틀린 항목만 버리고 나머지는 쓴다.
#    1) 목록이 아니면 빈 목록
#    2) 문자열로 바꿔 앞뒤 공백 제거
#    3) 비었거나 · 안에 공백이 있거나 · 2글자 미만이면 버림
#    4) 중복은 처음 나온 것만
#
# -in: raw = yaml 에서 읽은 suffixes 값(아무 모양)
#
# -out: list = 쓸 수 있는 끝말 목록
# -out: error = 없음
#------------------------------------------------------------------
def _clean_suffixes(raw):
    if not isinstance(raw, list):
        return []
    out = []
    for x in raw:
        w = str(x if x is not None else "").strip()
        # 한 글자 끝말("서")은 거의 모든 이름을 이상하게 끊는다.
        if len(w) < 2 or any(c.isspace() for c in w) or w in out:
            continue
        out.append(w)
    return out

위는 설계 이해용 스케치다. 구현 때 CLAUDE.md 주석 규칙에 맞춰 다듬는다.

10결과가 달라지지 않는 근거

  1. core 목록 = 내장 목록 — 같은 43개를 옮긴다.
  2. 정렬해도 같다 — 현재 43개 중 한 끝말이 다른 끝말의 끝토막인 쌍이 0개다(2026-09-15 확인). 끝토막 관계가 없으면 어느 이름에든 걸리는 끝말은 최대 하나라 차례가 결과를 바꾸지 않는다.
  3. 한 글자 끝말 0개 — 검증으로 버려지는 항목이 없다.
  4. 골든 테스트 — Rust/tests/fixtures/policy/synonyms 는 칸이 없는 옛 사전이라 내장 목록을 탄다. 정답표(Rust/tests/docvocab_golden.json, 수동 생성)를 다시 뽑을 필요가 없다.
