UI/UX 설계 · Human-in-the-loop Classification

문서 C·S·O 분류
— 워크플로 & UI/UX 설계

문서중앙화로 수집된 문서를 기밀·민감·공개(C/S/O)로 분류한다. 규칙(내용·경로·파일명)으로 1차 확정하고, 관리자가 큐레이션한 seed 문서와의 임베딩 비교로 보류분을 구제하며, 확정 결과를 다시 seed로 승격하는 능동학습 루프를 UI로 돌린다.

문서유형 UI/UX 설계 대상 문서중앙화 C/S/O 분류 엔진 csoclassify(추출·임베딩) + classify UI Streamlit 작성일 2026-08-13
한 줄 요약

규칙 설정 → seed 수집·확정 → 분류 → seed 갱신의 4단계 루프. 핵심은 관리자가 검증한 class_seed.jsonl(등급·벡터가 든 씨앗 저장소)이며, 분류는 규칙으로 확정하고 보류분만 seed와 임베딩 비교로 후보를 만든 뒤 사람이 확정한다. 확정분을 seed에 되먹여 정확도가 스스로 올라간다.

01

개요 — 능동학습 분류 루프

이 도구는 RAG가 아니라 문서 거버넌스(등급 분류)가 목적이다. 자동 분류는 완벽할 수 없으므로, 사람이 근거를 보고 확정하고 그 결정을 다음 분류에 재사용하는 human-in-the-loop 구조로 설계한다.

Curated Seed
검증된 씨앗이 기준

관리자가 확정한 C/S/O 문서(등급+벡터)를 class_seed.jsonl에 모아 분류의 기준으로 삼는다.

Rules First
규칙 우선, 임베딩은 구제

PII·기밀사전·경로·파일명으로 확정하고, 어느 것도 못 잡은 보류 문서만 seed와 임베딩 비교로 후보를 만든다.

Human Verify
사람이 최종 확정

모든 자동 등급은 관리자가 근거를 보고 승인·수정한다. 수정은 감사 로그로 남는다.

Feedback Loop
확정분을 seed로 되먹임

확정된 대표 문서를 seed에 추가 → seed가 늘수록 보류율이 줄고 정확도가 올라간다.

02

전체 워크플로

원안의 4단계를 유지하되, 규칙 설정을 앞단계(Phase 0)로 분리하고 seed 수집/확정을 명확히 구분했다. Phase 3·4가 정상상태에서 반복되는 루프다.

Phase 0 — 설정(1회/수시)
규칙 설정

PII 정규식·기밀사전·경로 택소노미·파일명 키워드·임계값을 UI에서 편집 → cso_rules.yaml(버전 관리)

↓
Phase 1 — 수집
seed 후보 수집

폴더 선택 → csoclassify --classify --with-vector → cso_result.jsonl(자동 등급 + 벡터)

↓
Phase 2 — 큐레이션
seed 확정

검토 UI로 근거 보고 C/S/O 확정 → 승인분을 seed로 승격 → class_seed.jsonl 생성/보강(등급+벡터+메타)

↓
Phase 3 — 분류(반복)
대상 문서 분류

파일/폴더 → csoclassify --classify --with-vector --propagate --seeds class_seed.jsonl → 보류분을 seed와 비교 → 검토 UI에서 확정

⟳ Phase 3 ↔ 4 정상상태 루프 — seed가 늘수록 보류·오분류가 줄어든다
Phase 4 — 되먹임(반복)
seed 갱신

① 확정분 중 대표 문서를 승격 ② 관리자가 신규 파일 직접 업로드 → csoclassify로 벡터 산출 → 추가 ③ 기존 seed 수정·삭제·등급변경. near-dup 중복 경고, 감사 로그

↓
Output
확정 C/S/O 분류 + 감사 기록

최종 등급 CSV/JSONL 내보내기 → 문서중앙화 시스템이 접근권한 적용

03

원안 검토 & 개선 제안

원안은 방향이 옳다. 아래는 견고성·정확도·운영성을 높이기 위한 보완이다.

구분원안개선/보완
규칙 설정Phase 1에 포함Phase 0로 분리 — 규칙 편집 화면 + 버전 관리(변경 시 소급 재분류 가능)
seed 저장소class_seed.jsonl외부 curated store로 명시 — 엔트리에 벡터 저장(재임베딩 방지), 등급·출처·승인자·시각 메타 포함
분류의 seed 비교seed_class와 임베딩 비교구현 갱신 필요: 전파가 외부 --seeds를 받도록(현재는 코퍼스 내부 seed 사용)
등급 결정임베딩으로 C/S/O규칙 우선, 보류만 임베딩 구제(과분류 방지). 단 near-dup(사본)은 예외 상향 옵션
seed 추가(Phase 4)관리자가 선택 추가near-dup 중복 경고(이미 있는 seed와 코사인≈1이면 정보 없음) + 등급별 균형 표시
실행 방식csoclassify.exe 수동UI에서 실행 트리거 — 폴더 선택→진행률→결과 자동 로드(CLI 왕복 제거)
감사—감사 이원화: cso_override.jsonl(분류 수정) + class_seed_audit.jsonl(seed 추가·수정·삭제)
핵심

가장 중요한 개선은 class_seed.jsonl을 벡터까지 담은 외부 큐레이션 저장소로 못박고, 분류(Phase 3)가 그 파일을 --seeds로 받아 비교하게 하는 것이다. 이래야 "관리자가 검증한 기준"으로 신규 문서를 분류하는 원안 의도가 성립한다.

균형 리포트
  • 능동학습(승격): 확정분 중 대표성 있는 문서만 골라 seed로 → 무분별 추가는 저장소만 키움.
  • 직접 업로드 추가: 분류 배치를 거치지 않고, 관리자가 신규 파일을 업로드하면 csoclassify가 텍스트 추출→벡터 산출, 관리자가 등급(C/S/O)을 지정해 class_seed.jsonl에 바로 추가한다(source="upload").
  • 인라인 편집(수정·삭제): seed 목록에서 각 항목의 등급 변경·메모 수정·삭제를 직접 수행. 잘못 넣은 seed는 즉시 정정(오염 방지).

06

상호작용 · 판정 원칙

Rules First
규칙 우선

rule/path/name로 확정된 등급은 임베딩이 흔들지 않는다(과분류 방지). 임베딩은 보류 구제가 기본.

Upgrade-only
상향 전용

최종=max(신호들). 임베딩은 올리기만, 내리지 않는다. 애매하면 검토 큐로.

Explainable
근거 필수

모든 등급에 근거(걸린 단어·건수·경로·이웃 seed)를 표시 → 관리자 납득·이의제기 대응.

Auditable
전 과정 감사

분류 수정·seed 변경을 누가·언제·왜와 함께 append-only 로그로 보존.

주의

임베딩은 주제는 잡아도 민감도 자체는 보증 못 한다(공개 안내문이 기밀 문서와 주제상 이웃일 수 있음). 그래서 seed 비교는 보류 구제·상향에만 쓰고, near-dup(사본)이 아닌 이상 이미 확정된 공개 문서를 끌어올리지 않는다.

08

구축 로드맵

STEP 1
외부 seed 비교 (--seeds)

전파가 class_seed.jsonl을 SeedIndex로 로드하도록. Phase 3의 근간.

STEP 2
seed 승격 + 관리 화면

"seed로 승격" 액션 · 신규 파일 직접 업로드 추가(csoclassify→벡터→등급지정) · seed 목록 인라인 편집(등급변경·삭제) + 감사.

STEP 3
UI에서 csoclassify 실행

폴더 선택→실행→결과 자동 로드. 수동 CLI 왕복 제거.

STEP 4
규칙 편집 화면(Phase 0)

기밀사전·경로·임계값 편집 + 샘플 미리보기 + 버전 태그.

STEP 5
균형·중복 리포트

등급별 seed 구성, near-dup 경고, 검토 큐 최적화.
