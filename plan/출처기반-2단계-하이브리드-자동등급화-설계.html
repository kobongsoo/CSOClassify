상세 설계 · Information Discovery

출처 기반 · 2단계 하이브리드 자동 등급화

출처만으로 대부분을 즉시 확정하고, 애매하거나 위험 신호가 있는 파일만 내용으로 재확인한다 — 속도와 정확도, 그리고 프라이버시를 동시에.

문서유형 상세설계 대상 InfoDiscovery + 사내 RAG 거버넌스 등급체계 C / S / O 작성일 2026-08-11
한 줄 요약

Stage 1(출처) 로 70~85%를 내용 열람 없이 확정하고, Gatekeeper 가 "불명·충돌·고위험" 파일만 골라 Stage 2(내용) 로 넘긴다. 충돌 시엔 항상 높은 등급 우선(Fail-safe), 최종 등급은 그대로 AI/RAG 인덱싱의 관문이 된다.

01

설계 원칙

출처 기반은 빠르지만 흔적에 의존하고, 내용 기반은 정확하지만 무겁고 프라이버시 부담이 있다. 두 방식을 순차로 엮어 서로의 약점을 메운다.

Fast-path
출처 우선 확정

출처만으로 확신되는 파일은 내용 스캔 없이 즉시 확정. 목표 커버리지 70~85%.

Selective
의심 파일만 정밀검사

불명·충돌·고위험 신호가 있는 파일만 Stage 2로 라우팅. 비용을 아낀다.

Fail-safe
안전측 기본값

판정 불가·충돌 시 낮은 등급이 아니라 높은 등급으로 보수 처리.

Privacy
내용 노출 최소화

Stage 2도 사람이 아닌 기계가 패턴만 확인. 로그엔 검출 결과만 남긴다.

Auditable
근거·신뢰도 기록

모든 판정에 근거 경로·신뢰도·룰 버전 기록 → 감사·이의제기 대응.

2.5

초기 코퍼스 부트스트랩 — Cold-start

위 파이프라인은 정상 유입(steady-state) 을 전제로 한다. 그러나 저장소에 이미 쌓여 있던 최초 문서 덩어리는 출처 흔적이 거의 없어 S_origin ≈ 0 으로 떨어진다 — 이건 별도의 일회성 문제다.

진단

초기 문서엔 출처기반을 쓰지 않는다. Zone.Identifier는 사내·USB·로컬 파일엔 없고 저장소로 수집(복사)하는 행위가 오히려 벗겨낸다. 저장소 볼륨의 $MFT는 "저장소에서 생성됨"만 말할 뿐 원본 머신의 MFT는 손에 없으며, 브라우저 DB는 과거분을 못 덮는다.

재정의 — 비율을 뒤집고, MpowerClassify 인덱싱에 인라인

정상상태가 "출처 우선, 내용은 예외"라면, 부트스트랩은 "내용·맥락 우선, 출처는 보너스" 로 뒤집는다. 그리고 이 일회성 분류를 MpowerClassify 인덱싱 단계 안에 붙인다 — 텍스트와 벡터가 이미 그 자리에서 생성되므로 분류 신호가 사실상 공짜로 딸려온다.

문서 → [사이냅] 텍스트 → ┌─ 분류신호 추출(경로·PII·키워드)  ┐
                          │                                  ├→ 등급라벨 → 인덱싱(등급태그)
        [ONNX] 벡터 ──────┴─ 임베딩 라벨 전파 ───────────────┘

부트스트랩 신호 계층 (값싼 것부터)

계층신호파일 여는가초기 코퍼스 유효성
B1컨테이너/경로 택소노미 — 수집원 폴더·파일서버 ACL·소유자 SID·기존 DRM 태그✕★★★ 원본 경로를 기록했다면 최고의 "출처 대용"
B2파일명·확장자·문서 속성 패턴 (계약서_, 대외비, 작성자)✕★★☆
B3내용 규칙 스캔 — MpowerClassify가 이미 뽑은 텍스트에 정규식·기밀 사전 적용이미 추출됨★★★ 어차피 임베딩하려 연 텍스트 → 무겁지 않다

B4 — 임베딩 라벨 전파 (킬러 카드)

Seed
라벨 씨앗

B1~B3에서 고신뢰로 등급이 붙은 문서 + 등급/주제별 소량의 사람 검증 앵커셋.

Propagate
벡터 전파

미분류 문서 → 가까운 seed 이웃의 등급을 k-NN·센트로이드로 부여. 임계 미만은 검토 큐.

Dedup
중복 즉시 상속

코사인 ≈ 1.0 near-duplicate(같은 계약서가 여러 폴더에 복사)는 사본 전체가 한 번에 상속 → 대량 정리.

주의

임베딩은 주제·의미를 잡지 민감도 자체를 보증하지 못한다(공개 안내문과 기밀 급여대장이 이웃일 수 있다). 전파 결과는 "후보 등급"일 뿐 — 상향·확인에만 쓰고 임베딩만으로 하향 금지. 강한 ACL·기밀 사전 히트는 임베딩보다 규칙을 우선한다.

T0 잔여 · 미분류/저신뢰검토 큐 → 사람 확인 → seed 승격 → 재전파
T1+ · 신규 유입출처기반 fast-path 복원 (Stage 1~6). 수집기가 원본 경로·ACL·소유자를 provenance로 기록
Fail-safe

부트스트랩에서 해소 안 되면 기본 S, 강한 ACL 제한 파일은 기본 C. 초기 1회는 샘플링 검수로 정확도를 보정한다.

Stage 1 — 출처 기반 고속 분류 · T1+ 신규 유입

04

Gatekeeper — 라우팅 결정

Stage 2는 비싸다. 아래 조건 중 하나라도 걸릴 때만 정밀검사로 보낸다. 출처가 O 라도 무조건 통과시키지 않고, 고위험 확장자·대용량 문서는 샘플링해 "공개 출처에 기밀 끼워넣기"를 잡는다.

def route(f):
    if f.S_origin >= 70 and not f.conflict:
        return "FASTPATH_CONFIRM"          # 출처만으로 확정 (내용 안 봄)

    if f.S_origin == 0:            # ① 출처 불명
        return "STAGE2"
    if f.conflict:                 # ② 경로 간 출처 충돌
        return "STAGE2"
    if f.origin_grade in (C, S) and f.ext in RISKY_EXT:   # ③ 고위험 확인용
        return "STAGE2"
    if f.moved_to_removable or f.recently_repackaged:      # ④ USB반출·재압축
        return "STAGE2"

    return "FASTPATH_CONFIRM"
목표 비율

Fast-path 확정 ≈ 75%, Stage 2 정밀 ≈ 25% (이 중 실제 등급 상향은 소수). 이 비율이 좋을수록 비용·프라이버시 부담이 낮은 설계다.

05

Stage 2 — 내용 기반 정밀 분류

의심 파일만, 그것도 사람이 아닌 기계가 계층적으로 검사해 내용 위험도 C_content (0~100) 와 근거를 산출한다.

계층방법탐지 예
L1정규식 패턴 매칭주민번호·카드번호·계좌·여권번호
L2키워드/기밀 사전"대외비", "인사평가", "M&A", 프로젝트 코드명
L3구조 분석 (표·폼 밀도)명단·표 형태 → 개인정보 대량 정황
L4(선택) 분류 ML / 임베딩계약서·재무제표·설계도 유형 자동 인식
Privacy

탐지된 실제 값(주민번호 원문 등)은 저장하지 않는다. "주민번호 패턴 12건 검출"처럼 메타 결과만 로그에 남겨 등급 판정의 프라이버시 부담을 제거한다.

06

최종 등급 결정 — 충돌 해소

출처와 내용이 다를 때가 핵심이다. 보수적으로 높은 등급을 우선한다.

최종등급 = 등급최댓값( 출처등급 , 내용등급 )   # C > S > O
출처 판정내용 판정최종의미
O 공개주민번호 대량 검출C공개 출처에 숨은 기밀을 잡아냄 ✓
C 기밀특이사항 없음C내용 못 봤다고 낮추지 않음(출처 신뢰 유지)
불명대외비 키워드S~C출처 없어도 내용으로 확정
불명특이사항 없음SFail-safe: 모르면 중간등급, 검토 대기
원칙

내용으로 등급을 올릴 순 있어도 함부로 내리지 않는다. 하향은 승인 워크플로를 경유하며, 근거가 약한 애매지대는 "검토 큐"로 보내 담당자가 최종 확인한다 — 이 큐가 작을수록 좋은 설계.

  • 외부 생성형 AI 완전 차단 (RBI 픽셀 반출도 불가)

Sensitive

공개
Open
  • 생성형 AI 자유 활용 허용

RAG 인덱싱 게이트

확정 등급을 AI 파이프라인의 관문으로 쓴다. 인덱싱 단계에서 등급 메타데이터를 문서 청크마다 태깅하면, 챗봇이 답변할 때 사용자 권한에 따라 C 청크를 자동 필터링할 수 있다.

단계별 도입 로드맵

PHASE 0
룰셋 정의

출처→등급 매핑 정의, 기밀 서버·URL 목록화 → 룰 기반 확보.

PHASE 1
Stage 1 가동 + 소급

출처 분류만 우선 가동, 과거 문서 일괄 등급화 → 대량 1차 커버.

PHASE 2
하이브리드 완성

Gatekeeper + Stage 2 결합 → 오분류 축소.

PHASE 3
AI/RAG 연동

인덱싱 게이트 연동, 등급별 정책 자동화 → 실사용.

PHASE 4
운영 안정화

재평가·감사·룰셋 튜닝 루프 정착.
