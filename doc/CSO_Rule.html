0 개요 · 파일 위치

cso_rule.yaml은 문서를 C(기밀)/S(민감)/O(공개)로 분류하는 정책 파일입니다. 실행파일(csoclassify)에 내장하지 않고 exe 옆의 외장 파일로 두어, 재빌드 없이 규칙만 교체·배포할 수 있습니다.

찾는 순서(우선)위치
① 환경변수CSOCLASSIFY_POLICY_DIR 폴더의 cso_rule.yaml
② 인자--rules <파일경로> 로 직접 지정
③ 기본(배포)exe 와 같은 폴더의 cso_rule.yaml

파일이 없으면 분류 실행 시 “어디에 두라”는 안내를 내고 종료(코드 3)합니다. 편집은 이 파일을 직접 수정하거나 UI 규칙설정에서 합니다(UI는 주석을 보존하며 저장 시 .bak 백업 + 버전 자동 상향).

프라이버시 불변식 — 스캐너는 매칭된 원문 PII 값을 저장하지 않습니다. 결과 근거에는 유형 id·건수·정책 키워드만 남습니다(원문은 --with-pii 옵션 사용 시에만 --out 파일에 한정).

공통 개념 — 등급이 정해지는 방식

한 문서에는 여러 판정 신호가 붙고, 최종 등급은 가장 민감한 등급으로 융합됩니다(보수적 max). 각 신호는 등급을 올릴 수만 있고 함부로 내리지 않습니다.

신호규칙셋 섹션무엇을 보나
rule 내용regex_pii + pii_combos + keywords본문의 PII 유형·결합·기밀 키워드
sensitive 민감정보sensitive법상 민감정보 범주 키워드
stamp 표식stamps문서에 찍힌 보안분류 스탬프
name 파일명keywords[].filename파일 이름 속 단어 2026-09-08 부터 본문(terms)과 별도 목록
embed 전파(규칙셋 아님 · seed 비교)보류 문서를 유사도로 구제(2차 패스)

bulk 상향: 한 유형이 임계값(건수) 이상 나오면 bulk_grade로 상향됩니다(명단·대장 정황). 예) 주민번호 1건=S, 5건 이상=C.

seed_eligible: 오탐이 적어, 이 근거로 확정된 문서를 임베딩 전파의 씨앗(seed)으로 승격해도 안전한지 여부입니다.

공통 값 — grade · weight · bool

값 종류가능한 값의미
gradeC S O기밀 > 민감 > 공개. 서열이 높을수록 민감. (미지정=신호 없음)
weighthigh · medium · low신뢰도 가중. confidence 표를 통해 0~1 신뢰도로 변환됨. 등급은 바꾸지 않음(검토 큐 편입·정렬용).
booltrue · false참/거짓 (예: seed_eligible, acl_restricted, always).

※ 신뢰도(confidence)는 “저신뢰면 사람이 검토” 같은 검토 큐 편입/정렬에만 쓰이고, C/S/O 등급 자체는 항상 max 융합으로 정해집니다.

1 version

규칙셋의 버전 문자열. 감사·추적용으로 분류 결과의 rule_version에 그대로 기록됩니다.

version: "cso-2026.08.3"
필드필수타입의미
version선택문자열규칙셋 버전. 관례상 cso-YYYY.MM.rev. 없으면 "unknown". UI 저장 시 rev 가 자동 +1.

2 defaults

개별 규칙이 값을 지정하지 않았을 때 쓰는 전역 기본값.

defaults:
  bulk_threshold: 5          # 5건 이상이면 bulk 상향
  case_insensitive: true     # 영문 키워드 대소문자 무시
필드필수타입기본의미
bulk_threshold선택정수5규칙에 개별 임계값이 없을 때 쓰는 전역 bulk 임계값. 이 건수 이상이면 bulk_grade로 상향.
case_insensitive선택booltruetrue면 키워드·표식·민감정보 매칭 시 영문 대소문자를 무시.

3 confidence

각 신호의 weight(high/medium/low)를 0~1 신뢰도로 바꾸는 표. 없으면 코드 기본값을 씁니다. 등급은 바꾸지 않습니다(검토 큐 편입·정렬용).

confidence:
  regex:     {high: 0.90, medium: 0.70, low: 0.50}   # 정규식 PII
  keyword:   {high: 0.85, medium: 0.70, low: 0.50}   # 기밀사전
  sensitive: {high: 0.85, medium: 0.70, low: 0.55}   # 민감정보군
  stamp:     {high: 0.95, medium: 0.80, low: 0.65}   # 보안분류 스탬프
  name:      0.60                                      # 파일명(고정)
키타입의미
regex{high,medium,low}PII(regex_pii)·결합(pii_combos) 신호의 신뢰도.
keyword{high,medium,low}기밀사전(keywords) 신호의 신뢰도.
sensitive{high,medium,low}민감정보군(sensitive) 신호의 신뢰도.
stamp{high,medium,low}보안분류 스탬프(stamps) 신호의 신뢰도(오탐 낮아 높게).
name실수(float)파일명 신호의 고정 신뢰도(힌트라 단일 값).

※ 일부만 적어도 됩니다(적은 값만 기본값 위에 덮어씀). 값은 0~1 실수.

4 regex_pii rule 신호 · L1

개인식별정보(PII) 유형→등급 정책. 검출은 ko-pii 엔진(패턴·체크섬·문맥·우회방어 내장)이 담당하고, 여기서는 “그 유형이 몇 건이면 몇 등급인가”만 정합니다.

regex_pii:
- id: rrn
  name: 주민등록번호
  label: RRN
  base_grade: S
  bulk_grade: C
  weight: high
  seed_eligible: true
필드필수타입기본의미
id필수문자열—유형 식별자. 결과 근거의 id(예: rrn).
name선택문자열=id사람이 읽는 이름(예: 주민등록번호).
label필수문자열—대응하는 ko-pii 라벨(예: RRN,CARD,ADDRESS). 이 라벨만 검출 대상이 됨. (별칭 kopii_label 도 허용)
base_grade선택gradeS1건이라도 있으면 부여할 등급.
bulk_grade선택grade없음임계값 이상일 때 상향할 등급. 없으면 상향 안 함(항상 base_grade).
bulk_threshold선택정수defaults이 유형 전용 임계값. 없으면 defaults.bulk_threshold. 검출 건수가 이 값 이상이면 bulk_grade.
weight선택weightmedium신뢰도 가중.
seed_eligible선택boolfalsetrue면 이 히트로 확정된 문서를 전파 seed 로 승격 가능.
활성 PII는 20종(RRN·FRN·CARD·ACCOUNT·PASSPORT·DRIVER_LICENSE·PHONE·EMAIL·BUSINESS_REG·CORP_REG·ADDRESS·MEDICAL_INSURANCE·PRESCRIPTION_ID·EDI_DRUG·VEHICLE·COURT_CASE·PNU·NATIONALITY·URL·IP). cso_rule.yaml에 매핑된 라벨만 검출합니다(미등록 유형은 스캔 안 함).

5 pii_combos rule 신호 · L1-combo

결합식별성(개인정보보호법·GDPR ‘결합용이성’) — 개별론 등급이 낮아도 여러 PII 유형이 한 문서에 모이면 재식별 위험이 커져 상향합니다. 판정은 문서 단위 공존만 봅니다(문장 근접성 아님). 결과에는 layer:"COMBO" 히트로 표시됩니다.

pii_combos:
- id: identity_financial
  name: 신원+금융 결합(재식별·금융피해)
  all_of: [RRN, ACCOUNT]       # 둘 다 있으면 성립
  grade: C
  weight: high
  seed_eligible: true

- id: contact_cluster
  name: 연락처 결합(개인 특정)
  of: [PHONE, EMAIL, ADDRESS]  # 이 그룹에서…
  min_types: 2                 # …2종 이상이면 성립 → S
  grade: S
필드필수타입기본의미
id필수문자열—조합 식별자.
name선택문자열=id사람이 읽는 이름.
all_of조건①라벨 목록없음나열한 ko-pii 라벨이 모두 있으면 성립.
of조건②라벨 목록없음min_types와 함께 사용하는 라벨 그룹.
min_types조건②정수0of 그룹에서 서로 다른 라벨이 이 종수 이상이면 성립.
grade선택gradeC조합 성립 시 부여할 상향 등급.
weight선택weighthigh신뢰도 가중.
seed_eligible선택boolfalsetrue면 이 조합으로 확정된 문서를 seed 로 승격 가능.

※ all_of와 of+min_types를 둘 다 적으면 둘 다 만족해야 합니다(AND). 조건을 하나도 안 적은 규칙은 무시됩니다(오발동 방지).

6 keywords rule 신호 · L2 · name 신호

기밀사전 — 지정 단어가 있으면 히트. 본문과 파일명을 따로 적습니다: terms 는 본문(추출 텍스트)에서 rule 신호의 L2로, filename 은 파일 이름(폴더 제외)에서 name 신호로 쓰입니다.

name(파일명) 신호는 별도 섹션이 아니라 이 규칙의 filename 칸입니다. filename 을 안 적으면 그 규칙은 파일 이름을 보지 않습니다 — terms 를 빌려 쓰지 않습니다. 예: mark_confidential 에 filename: [대외비] 를 적어 두면 대외비_보고서.hwp 라는 파일명만으로도 C 가 잡힙니다. PII 정규식(regex_pii)·스탬프(stamps)·민감정보(sensitive)는 내용 전용이라 파일명엔 적용되지 않습니다.
왜 나눴나 2026-09-08 변경 — 예전에는 terms 를 파일명에도 그대로 썼습니다. 그 탓에 실측(문서 2,266개)에서 파일명 신호 99건 중 79건이 제품명 규칙 하나에서 나왔습니다 — 엠파워 V10 사용자 매뉴얼.pptx 같은 제품 매뉴얼이 이름 때문에 C 가 됐습니다. 본문에 제품명이 나오는 것과 파일명이 그 제품 문서인 것은 뜻이 다른데, 예전 문법으로는 구분할 방법이 없었습니다.
keywords:
- id: mark_confidential
  name: 기밀 표식
  terms: [대외비, 극비, 기밀, CONFIDENTIAL, RESTRICTED, SECRET]   # 본문에서 찾을 말
  filename: [대외비, 극비, 기밀, CONFIDENTIAL]                     # 파일명에서 찾을 말(생략 가능)
  base_grade: C
  weight: high
  seed_eligible: true
필드필수타입기본의미
id필수문자열—규칙 식별자.
name선택문자열=id사람이 읽는 이름.
terms필수문자열 목록—탐지 단어들. 하나라도 본문에 있으면 히트(부분일치). case_insensitive 정책 적용.
filename선택문자열 목록없음파일 이름에서 찾을 단어들. 안 적으면 이 규칙은 파일명 신호를 만들지 않습니다(terms 로 되돌아가지 않음). exclude 는 파일명에도 함께 적용됩니다. 2026-09-08 신설
exclude선택문자열 목록없음오탐 제외어. 단어가 이 문구 안에 든 매치는 세지 않음(한국어는 띄어쓰기가 없어 부분일치 오탐이 잦음). 예: 전과 이지만 산전과·발전과 는 제외.
base_grade선택gradeS1건이라도 있으면 부여할 등급.
bulk_grade선택grade없음총 등장 건수가 임계 이상이면 상향할 등급.
bulk_threshold선택정수defaults이 규칙 전용 임계값(없으면 defaults).
weight선택weightmedium신뢰도 가중.
seed_eligible선택boolfalsetrue면 seed 승격 가능.

※ 결과 근거에는 어떤 단어가 몇 번 걸렸는지(terms:[{term,count}])가 남습니다(정책 키워드라 안전).

7 sensitive sensitive 신호 · Signal F

법상 민감정보(개인정보보호법 제23조: 건강·유전·성생활·사상/신념·정치·노조·범죄경력·인종). 일반 기밀사전과 분리된 독립 신호라, “어느 민감범주 때문에 등급이 올랐는지”가 결과에서 명확히 드러납니다.

sensitive:
- id: health
  name: 건강정보
  category: 건강
  grade: C
  weight: high
  seed_eligible: false
  terms: [진단서, 진단명, 병력, 질병명, 진료기록, 투약내역, ...]
필드필수타입기본의미
id필수문자열—규칙 식별자(예: health).
name선택문자열=id사람이 읽는 이름.
category선택문자열""민감정보 범주(건강/유전/성생활/사상·정치/노조/범죄경력/인종). 근거에 표기돼 감사에 유용.
terms필수문자열 목록—탐지 단어들(부분일치, case_insensitive 적용).
exclude선택문자열 목록없음오탐 제외어. 단어가 이 문구 안에 든 매치는 세지 않음. 예: 전과 이지만 산전과 산후 는 제외(criminal 규칙에 기본 적용됨).
grade선택gradeC히트 시 부여 등급(법상 민감 → 기본 C).
weight선택weighthigh신뢰도 가중.
seed_eligible선택boolfalsetrue면 seed 승격 가능.
키워드 기반이라 오탐 가능(예: 일반 기사 속 ‘정치’). 보수적(상향)으로 두고, 과분류는 검토 큐에서 사람이 흡수합니다. 조직 문서 특성에 맞게 terms를 가감하세요.

8 stamps stamp 신호 · Signal E

보안분류 스탬프 — 문서에 찍힌 “작성자의 명시적 분류 의도”. 일반 키워드와 달리, 본문 단발 언급(“대외비가 아님”)의 오탐을 막으려 머리에 있거나 반복일 때만 인정합니다.

stamps:
- id: stamp_confidential
  name: 대외비/기밀 스탬프
  grade: C
  weight: high
  seed_eligible: true
  terms: [대외비, 극비, 기밀, CONFIDENTIAL, SECRET]

- id: stamp_confidential_phrase
  name: 기밀 취급문구(명시)
  always: true                 # 위치/반복 무관 1건도 인정
  grade: C
  terms: [관계자 외 열람금지, 무단복제금지, ...]
필드필수타입기본의미
id필수문자열—규칙 식별자.
name선택문자열=id사람이 읽는 이름.
terms필수문자열 목록—표식 문구들(예: 대외비,CONFIDENTIAL).
grade선택gradeC스탬프 인정 시 부여 등급(내부용은 S 등).
weight선택weighthigh신뢰도 가중.
seed_eligible선택boolfalsetrue면 seed 승격 가능.
always선택boolfalsetrue면 위치/반복 게이트 없이 1건이라도 인정(거의 스탬프 전용 문구용).

왜 뺐나 — 문서가 어디 놓여 있는지는 담당자가 옮기면 바뀝니다. 위치로 기밀을 정하면 폴더 정리 한 번에 등급이 흔들립니다. 실측(레코드 3,715건)에서도 거의 안 쓰였고, 쓰인 것은 틀렸습니다:

path 가 등급 결정에 참여   :  27건 (0.7%)
path 만으로 등급이 정해짐  :   8건 (0.2%)  ← 전부 오탐
acl_restricted fail-safe   :   0건        ← 안전망이 한 번도 안 걸림

규칙의 match 조각에 슬래시 없는 말(보안파일서버)이 섞여 있어, "보안파일서버"라는 제품의 설치확인서가 보안 서버의 파일로 취급됐습니다. 공개 평가 데이터셋도 폴더 이름(finance·public) 때문에 걸렸습니다. 경로 신호가 위치가 아니라 이름에 든 말을 보고 있었던 셈입니다.
