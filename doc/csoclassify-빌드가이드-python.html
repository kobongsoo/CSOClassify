Rust 포팅판(csoclassify-rs) 빌드는 별도 문서 csoclassify-빌드가이드-rust.html 를 보세요. 두 문서는 같은 순서로 구성돼 있어 비교해서 읽을 수 있습니다.

1 무엇을 만드는가

파이썬으로 짠 CSOClassify 를 파이썬이 설치돼 있지 않은 PC/서버에서도 돌아가는 폴더로 만듭니다. PyInstaller 가 파이썬 인터프리터와 필요한 라이브러리를 전부 _internal\ 폴더에 담아줍니다.

onedir 방식을 쓰는 이유
PyInstaller 에는 파일 하나로 만드는 onefile 과 폴더로 만드는 onedir 이 있습니다. 이 프로젝트는 onedir 만 씁니다 — onefile 은 실행할 때마다 임시폴더에 압축을 풀어 매번 느리고, 상주 데몬이 임시 snf_exe 경로를 잃어버리는 문제가 있었습니다. (build/csoclassify-onefile.spec 은 참고용으로만 남아 있습니다.)

완성된 배포본 구조

Windowsdist-onedir\windows\

csoclassify.exe 실행 본체 _internal\ 파이썬 런타임 + 라이브러리 cso_rules.yaml 보안등급 규칙셋(외장) doc_taxonomy.yaml 업무분류 체계 스냅샷(외장) doc_rule.yaml 업무분류 규칙셋(외장) class_seed.jsonl 전파 기준 seed models\e5-small-ko\ 임베딩 모델(외장) synap\windows\ ├ snf_exe.exe 사이냅 텍스트 추출기 └ snf_win.dll

실행본체+런타임 약 115MB, 외장 포함 약 500MB

Linuxdist-onedir/linux/

csoclassify-onedir-linux.tgz 실행본체+_internal 압축 cso_rules.yaml 보안등급 규칙셋(외장) doc_taxonomy.yaml 업무분류 체계 스냅샷(외장) doc_rule.yaml 업무분류 규칙셋(외장) class_seed.jsonl 전파 기준 seed models/e5-small-ko/ 임베딩 모델(외장) synap/linux/snf_exe 사이냅 추출기(정적링크) README.txt

tgz 52MB · 외장 포함 약 186MB

리눅스는 왜 폴더가 아니라 .tgz 인가?
_internal/ 안의 .so 파일들은 심볼릭 링크(예: libstdc++.so.6 → libstdc++.so.6.0.34) 로 얽혀 있습니다. Windows 파일시스템은 심볼릭 링크를 보존하지 못해, Windows 를 거쳐 폴더째 복사하면 링크가 깨집니다. 그래서 리눅스에서 tar 로 묶은 상태로 옮기고 리눅스에서 풉니다. (Rust 판은 심볼릭 링크가 없어 폴더 그대로 배포합니다.)

“외장 리소스” 개념

규칙셋·모델·사이냅 추출기는 exe 안에 넣지 않고 실행파일 옆에 둡니다. 이유는 세 가지입니다.

  • 규칙 교체가 자유롭다 — cso_rules.yaml 만 바꾸면 재빌드 없이 정책 변경
  • 기동이 빠르다 — 모델(129MB)을 매번 압축 해제하지 않음
  • 라이선스 분리 — 사이냅 문서필터는 상용 컴포넌트라 별도 배포

PyInstaller 는 크로스컴파일이 안 됩니다. Windows 에서 만든 결과물은 Windows 에서만, 리눅스에서 만든 결과물은 리눅스에서만 돕니다. PyInstaller 는 “지금 이 PC 에 설치된 파이썬 인터프리터와 .pyd/.so 를 그대로 복사”하는 방식이기 때문입니다. → 리눅스 배포본은 반드시 리눅스에서 빌드해야 합니다.
CentOS 7 에서 빌드하는 이유 — 리눅스 실행파일은 빌드한 glibc 버전 이상에서만 돕니다. glibc 2.17(CentOS 7)은 가장 낮은 축이라 여기서 빌드하면 이후 배포판 어디서나 실행됩니다. requirements.txt 의 라이브러리를 고를 때도 “CentOS7/glibc2.17 호환 wheel 이 있는가”를 기준으로 삼았습니다.

3 Windows 배포본 만들기

1 Python 설치 최초 1회만

python.org 에서 3.12.x 를 받아 설치합니다. 설치 첫 화면에서 Add python.exe to PATH 를 반드시 체크하세요.

python -V
Python 3.12.10 처럼 나오면 성공.

3.13 이상을 써도 대개 되지만, 확인된 조합은 3.12 입니다. 라이브러리 wheel 이 없어 막히면 3.12 로 맞추세요.

2 가상환경 만들고 라이브러리 설치

가상환경(venv)은 “이 프로젝트 전용 파이썬 방”입니다. 다른 프로젝트 라이브러리와 섞이지 않게 해줍니다.

cd /d D:\Project\CSOClassify

python -m venv .venv
.venv\Scripts\activate

python -m pip install --upgrade pip
pip install -r requirements.txt
프롬프트 앞에 (.venv) 가 붙으면 가상환경 안에 들어온 것입니다. 터미널을 새로 열 때마다 .venv\Scripts\activate 를 다시 실행해야 합니다.

회사 PC 에 이미 필요한 패키지가 다 깔려 있다면 venv 없이 그대로 진행해도 됩니다.

3 빌드

반드시 프로젝트 최상위 폴더(D:\Project\CSOClassify)에서 실행합니다. spec 파일이 os.getcwd() 를 기준으로 src\ 를 찾기 때문입니다.

cd /d D:\Project\CSOClassify
pyinstaller build\csoclassify.spec

2~4분 뒤 마지막에

INFO: Building COLLECT COLLECT-00.toc completed successfully.

가 나오면 성공. 결과물은 dist\csoclassify\ 입니다.

dist\csoclassify\ ├ csoclassify.exe 실행 본체 └ _internal\ 파이썬 런타임 + 라이브러리 (약 115MB)
WARNING: 줄은 대부분 무시해도 됩니다. 중요한 것은 맨 마지막에 completed successfully 가 나오는지와, 7장의 실행 테스트가 통과하는지입니다.

4 배포본 폴더에 조립

빌드 결과에 외장 리소스를 붙여야 완성입니다.

cd /d D:\Project\CSOClassify

:: (1) 실행본체 + 런타임
xcopy /E /I /Y dist\csoclassify  dist-onedir\windows

:: (2) 규칙셋(보안등급 · 업무분류) · 전파 seed
copy /Y resources\policy\cso_rules.yaml dist-onedir\windows\
copy /Y resources\policy\doc_taxonomy.yaml dist-onedir\windows\
copy /Y resources\policy\doc_rule.yaml dist-onedir\windows\

:: (3) 임베딩 모델
xcopy /E /I /Y resources\models\e5-small-ko dist-onedir\windows\models\e5-small-ko

:: (4) 사이냅 텍스트 추출기 (상용 컴포넌트 — 별도 확보)
xcopy /E /I /Y ..\MpowerAI_v10\pympower_ext\common\filter4-v4.29.0-windows_64bit_VC9\v4  dist-onedir\windows\synap\windows

사이냅(snf_exe.exe, snf_win.dll)은 --hybridparse 를 쓰면 폴백 용도로만 필요합니다. 없어도 대부분의 포맷은 오픈소스 파서로 처리됩니다.

4 Linux 배포본 만들기

리눅스 배포본은 리눅스 서버에서 빌드하고, 결과를 .tgz 로 묶어 Windows 로 내려받습니다.

1 소스를 압축해서 서버로 보내기

보낼 것은 소스와 spec 뿐입니다. 모델(129MB)·사이냅은 서버에 이미 있거나 별도로 배치합니다.

cd /d/Project/CSOClassify
tar -czf /tmp/cso_src.tgz src build requirements.txt

plink -batch -ssh -l mpower -pw '<PW>' 10.10.4.10 "mkdir -p /MOCOMSYS/.csoclassify/build_slim"
pscp  -batch -pw '<PW>' /tmp/cso_src.tgz mpower@10.10.4.10:/MOCOMSYS/.csoclassify/build_slim/

2 서버에서 환경 준비

ssh mpower@10.10.4.10

source /MOCOMSYS/anaconda3/etc/profile.d/conda.sh
conda activate bong
python -V                # Python 3.13.5
pyinstaller --version    # 6.22.0

cd /MOCOMSYS/.csoclassify/build_slim
tar xzf cso_src.tgz

패키지가 빠져 있으면 설치합니다.

pip install -r requirements.txt
conda 환경 bong 을 쓰는 이유 — 이 환경에는 CentOS 7 시스템보다 훨씬 최신인 libstdc++.so.6(6.0.34) 이 들어 있습니다. spec 파일이 이걸 자동으로 찾아 배포본에 넣어줍니다 (8-①). 시스템 파이썬으로 빌드하면 이 부분이 빠져 실행이 안 됩니다.

3 빌드

cd /MOCOMSYS/.csoclassify/build_slim
pyinstaller build/csoclassify.spec 2>&1 | tee build.log

결과물은 dist/csoclassify/ 입니다.

ls -la dist/csoclassify/
# csoclassify (약 8.3MB, ELF) + _internal/
venv 로 빌드한다면 — --system-site-packages venv 에서는 sys.prefix/lib 에 libstdc++.so.6 가 없습니다. 이때는 conda 라이브러리 경로를 직접 알려줍니다. 
export CSO_EXTRA_LIBDIR=/MOCOMSYS/anaconda3/envs/bong/lib
pyinstaller build/csoclassify.spec

4 서버에서 동작 확인

cd /MOCOMSYS/.csoclassify/build_slim/dist/csoclassify
./csoclassify --help
./csoclassify --classify --file /tmp/샘플.txt --rules /경로/cso_rules.yaml
ImportError: … CXXABI_1.3.9 not found 가 나오면 _internal/libstdc++.so.6 가 안 들어간 것입니다 → 8-①

5 tgz 로 묶어 Windows 로 내려받기

심볼릭 링크와 실행권한을 보존하려면 반드시 리눅스에서 tar 로 묶어야 합니다.

# 서버에서
cd /MOCOMSYS/.csoclassify/build_slim/dist
tar czf /tmp/csoclassify-onedir-linux.tgz csoclassify
ls -lh /tmp/csoclassify-onedir-linux.tgz     # 약 52MB
# Windows(Git Bash) 에서 내려받기
cd /d/Project/CSOClassify/dist-onedir/linux
pscp -batch -pw '<PW>' mpower@10.10.4.10:/tmp/csoclassify-onedir-linux.tgz .
이 tgz 를 Windows 에서 풀지 마세요. _internal 안의 심볼릭 링크가 깨져 리눅스에서 실행이 안 됩니다. 배포 대상 리눅스로 옮긴 뒤 그곳에서 tar xzf 하세요.

6 외장 리소스 붙이기

tgz 옆에 규칙셋·모델·사이냅(리눅스용)을 둡니다. 모델·규칙셋은 OS 무관 동일 파일이라 Windows 쪽에서 복사하면 됩니다.

cd /d/Project/CSOClassify/dist-onedir/linux
cp ../../resources/policy/cso_rules.yaml .
cp ../../resources/policy/doc_taxonomy.yaml ../../resources/policy/doc_rule.yaml .
cp ../windows/class_seed.jsonl .
mkdir -p models synap/linux
cp -r ../../resources/models/e5-small-ko models/
cp ../../resources/synap/linux/snf_exe synap/linux/

7 배포 대상 리눅스에서 설치

cd <복사한 폴더>
tar xzf csoclassify-onedir-linux.tgz          # 심볼릭링크·권한 복원
chmod +x csoclassify synap/linux/snf_exe
./csoclassify --classify --file "문서.pdf"

tgz 를 풀면 csoclassify/ 폴더가 생깁니다. 실행파일이 외장 리소스를 자기 옆에서 찾으므로, cso_rules.yaml·models/·synap/ 을 csoclassify/ 안으로 옮기거나 --rules/환경변수로 경로를 지정하세요.

6 spec 파일이 하는 일

build\csoclassify.spec 은 “PyInstaller 에게 무엇을 어떻게 묶을지” 알려주는 파이썬 스크립트입니다. 빌드가 이상하면 대개 여기를 봐야 합니다.

구역하는 일왜 필요한가
entry src\csoclassify_launcher.py 를 진입점으로 지정 PyInstaller 는 진입 스크립트를 __main__ 으로 실행하는데, 패키지 내부의 상대 import (from .cli …)를 쓰는 __main__.py 는 진입점이 될 수 없습니다. 런처가 절대 import 로 우회합니다
datas ko_pii 의 사전 파일(.txt.gz) 수집 PII 검출에 쓰는 행정구역·은행명 사전 등은 코드가 아니라 데이터라 자동으로 안 딸려옵니다
hiddenimports 동적으로 import 되는 모듈을 명시 PyInstaller 는 코드에 적힌 import 만 추적합니다. 문자열로 불러오는 모듈은 직접 적어줘야 실행 시 ModuleNotFoundError 가 안 납니다
binaries (리눅스만) libstdc++.so.6·libgcc_s.so.1 동봉 CentOS 7 의 시스템 libstdc++(4.8.5)는 onnxruntime/numpy 가 요구하는 CXXABI_1.3.9+ 를 제공하지 못합니다 (8-①)
excludes torch·transformers·PIL·lxml·pandas·jupyter 계열 등 제외 용량 슬림화의 핵심. 특히 리눅스 conda bong 은 데이터사이언스용이라 numba/llvmlite(153MB) 같은 게 딸려 들어올 수 있습니다. 런타임에 안 쓰므로 통째로 뺍니다
strip 리눅스에서만 .so 디버그 심볼 제거 용량 감소. Windows 는 strip 도구가 없을 수 있어 끕니다
COLLECT onedir 로 모으기 이 블록이 있으면 onedir, EXE 에 전부 넣으면 onefile 입니다
새 라이브러리를 추가했는데 실행 시 ModuleNotFoundError 가 난다면 → spec 의 hiddenimports 목록에 모듈 이름을 추가하고 다시 빌드하세요.

8 자주 나는 오류와 해결

① CXXABI_1.3.9 not found / GLIBCXX_3.4.2x not found Linux

ImportError: /lib64/libstdc++.so.6: version `CXXABI_1.3.9' not found
             (required by …/_internal/onnxruntime/capi/onnxruntime_pybind11_state.so)

원인 — CentOS 7 기본 libstdc++(gcc 4.8.5) 이 너무 낡았습니다.

해결 — 배포본 _internal/ 에 최신 libstdc++.so.6·libgcc_s.so.1 이 들어가야 합니다. spec 이 자동으로 넣어주지만, 찾지 못하면 조용히 건너뜁니다. 확인:

ls -la dist/csoclassify/_internal/libstdc++.so.6

없다면 conda 환경(bong)으로 빌드하거나, venv 라면 경로를 알려주고 다시 빌드하세요.

export CSO_EXTRA_LIBDIR=/MOCOMSYS/anaconda3/envs/bong/lib
pyinstaller build/csoclassify.spec

⑧ 구형 .doc/.xls/.ppt/.hwp 가 감지=binary 로 추출 실패 공통 2026-08-26 수정

[csoclassify] 추출 실패: /경로/취업규칙.doc :: 사용 가능한 추출기 없음(감지=binary)

원인 — src/csoclassify/extract/detect.py 의 OLE 매직 판정이 슬라이스를 빠뜨린 버전입니다. head 는 앞 2048바이트인데 8바이트 상수와 통째로 비교하면 절대 참이 되지 않아, .doc·.xls·.ppt·구형 .hwp(모두 OLE 복합문서)가 전부 binary 로 떨어집니다.

# 잘못된 판정 — 절대 참이 되지 않는다
if head == _OLE_MAGIC:

# 올바른 판정 — 바로 아래 ZIP 판정(head[:4])과 같은 방식
if head[:8] == _OLE_MAGIC:

왜 여태 안 보였나 — 사이냅이 설치된 환경에서는 binary 로 떨어져도 snf 폴백이 조용히 받아내 결과가 정상으로 보였습니다. 사이냅이 없는 리눅스 배포본에서만 드러납니다.

확인 — 소스 한 줄로 바로 볼 수 있습니다. doc 이 나와야 정상이고 binary 면 옛 버전입니다.

PYTHONPATH=src python -c "from csoclassify.extract.detect import detect_format; print(detect_format('샘플.doc'))"
고쳐도 기존 판정은 바뀌지 않습니다. d:\sample 18건을 등급뿐 아니라 판정 근거 용어까지 전수 대조한 결과 차이 0건이었습니다 — 자체 .doc 파서가 뽑는 텍스트가 사이냅이 뽑던 것과 규칙 판정 면에서 동등합니다. 달라지는 것은 사이냅이 없는 환경뿐으로, 검출 5 → 10, 추출실패 7 → 0 이 됩니다.
Rust 판(csoclassify-rs)은 CFB 컨테이너를 직접 열어 판정하므로 이 버그와 무관합니다. 재빌드가 필요 없습니다.

PyInstaller 는 중간 산출물을 캐시합니다. spec 을 고쳤는데 반영이 안 되면 지우고 다시 빌드하세요.
