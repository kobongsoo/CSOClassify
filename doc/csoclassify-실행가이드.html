1 빠른 시작

이 도구는 명령줄(CLI) 프로그램입니다. 더블클릭하면 검은 창이 깜빡이고 닫힙니다(정상) — 반드시 문서를 인자로 줘야 합니다.

이 폴더에서 터미널(주소창에 cmd 입력)을 연 뒤:

:: 문서 1개를 C/S/O 로 분류(기본 동작 — 모드 플래그 불필요)
csoclassify.exe --file "샘플.hwp"

:: 폴더 전체를 분류해 결과를 파일로 저장(가장 많이 쓰는 형태)
csoclassify.exe --dir "D:\collected" -r --embed-needed --format jsonl --out result.jsonl

:: 임베딩 벡터만 뽑기(분류 없이) — --embed
csoclassify.exe --embed --file "샘플.hwp"
처음 실행은 onedir 첫 기동과 모델을 메모리에 올리느라 수십 초 걸립니다(정상). 모델은 models\e5-small-ko\에 이미 풀려 있어 압축 해제 단계는 없습니다. 이후에는 모델이 메모리에 상주(데몬)해 빨라집니다.

2 패키지 구성

onedir 방식으로 패키징하며 Windows·Linux 2종을 각각 제공합니다 (dist-onedir\windows\, dist-onedir\linux\). 실행본체(csoclassify)와 파이썬 런타임(_internal\)이 한 폴더에 함께 있고, 규칙셋·모델·추출기는 그 옆에 외장 리소스로 둡니다. 모델은 이미 폴더로 풀려(models\e5-small-ko\) 있어 별도 압축 해제가 없습니다. 폴더 안의 상대 위치를 바꾸지 마세요.

① Windows — dist-onedir\windows\

windows\ ├─ csoclassify.exe 실행 파일(명령줄 도구) ├─ _internal\ 파이썬 런타임·의존 DLL(onedir). exe 와 한 세트 — 지우거나 옮기지 말 것 ├─ cso_rules.yaml C/S/O 분류 규칙셋(외장) — exe 옆에 필수. 재빌드 없이 교체 가능 ├─ cso_seed.jsonl 전파용 seed 저장소(선택) — 있으면 보류 문서 구제/승격에 사용 ├─ models\ │ └─ e5-small-ko\ 임베딩 모델(model.onnx 등). 폴더째 exe 옆에 — 압축 해제 불필요 ├─ synap\ │ └─ windows\ 사이냅 문서필터(텍스트 추출) — OS별 하위폴더 │ ├─ snf_exe.exe │ └─ snf_win.dll └─ log\ 실행 로그(자동 생성)
주의: _internal\은 exe 와 한 세트라 지우거나 따로 옮기면 실행이 안 됩니다. 추출기는 synap\windows\snf_exe.exe 경로에 있어야 합니다(과거처럼 synap\ 바로 아래 평평하게 두는 방식이 아님). 규칙셋 cso_rules.yaml·모델 models\e5-small-ko\는 exe 와 같은 폴더 기준으로 찾습니다. 규칙셋이 없으면 분류 실행 시 "어디에 두라"는 안내를 내고 종료(코드 3)합니다.

② Linux — dist-onedir/linux/

linux/ ├─ csoclassify-onedir-linux.tgz 실행본체(csoclassify + _internal). ※ 리눅스에서 풀어야 함(심볼릭링크·권한 보존) ├─ cso_rules.yaml C/S/O 분류 규칙셋(외장) ├─ cso_seed.jsonl 전파용 seed 저장소(선택) ├─ models/ │ └─ e5-small-ko/ 임베딩 모델(int8) ├─ synap/ │ └─ linux/ │ └─ snf_exe 텍스트 추출기(리눅스) └─ README.txt 설치·실행 안내

리눅스 설치·실행(리눅스 서버에서):

# 1) 이 폴더를 리눅스 서버로 복사한 뒤, 실행본체를 푼다(심볼릭링크·권한 보존)
cd <이 폴더> && tar xzf csoclassify-onedir-linux.tgz
# 2) 실행 권한 부여
chmod +x csoclassify synap/linux/snf_exe
# 3) 실행
./csoclassify --file "문서.pdf"
주의: .tgz는 반드시 리눅스에서 풀어야 합니다 — Windows 에서 풀면 심볼릭링크가 깨집니다. 압축을 풀면 csoclassify 실행본체와 _internal/이 나오며, cso_rules.yaml·synap/linux/snf_exe·models/e5-small-ko/는 csoclassify와 같은 폴더에 있어야 합니다.

3 실행 모드

모드는 플래그로 정해집니다. 아무 모드 플래그가 없으면 C/S/O 분류가 기본입니다. 임베딩 벡터만 필요하면 --embed, 추출 텍스트만 필요하면 --text-only 를 줍니다.

① C/S/O 분류 (기본) — 모드 플래그 불필요

여러 판정 신호(내용·민감정보·보안분류 스탬프·경로·파일명)로 등급을 판정합니다. --file/--dir 만 주면 바로 분류합니다(예전의 --classify 는 이제 붙일 필요가 없습니다). 출력은 기본 json — --file 단건은 객체 하나, --dir 배치는 레코드들의 JSON 배열 [ … ](그대로 뷰어로 열림)입니다. 줄단위로 스트리밍/처리하려면 --format jsonl(문서당 1줄).

검출 PII 유형 (20종 · 검출 엔진 ko-pii) — 문서에서 자동 검출하는 개인정보 유형과 기본등급입니다. 대량(bulk 임계 이상)이면 상향됩니다.

기본등급유형 (ko-pii 라벨)
S 민감주민등록번호(RRN) · 외국인등록번호(FRN) · 신용카드번호(CARD) · 계좌번호(ACCOUNT) · 여권번호(PASSPORT) · 운전면허번호(DRIVER_LICENSE) · 주소(ADDRESS) · 의약품EDI(EDI_DRUG) · 차량번호(VEHICLE) · 사건번호(COURT_CASE) · 부동산고유번호(PNU) · 국적(NATIONALITY)
C 기밀건강보험번호(MEDICAL_INSURANCE) · 처방전(PRESCRIPTION_ID)
O 공개 대량→S휴대전화번호(PHONE) · 이메일(EMAIL) · 사업자등록번호(BUSINESS_REG) · 법인등록번호(CORP_REG) · URL · IP주소(IP) 〔URL·IP 2026-08-15 추가〕

※ 검출은 ko-pii(패턴·체크섬·문맥·우회방어 내장)가 담당하고, 여기 표의 유형→등급 정책은 cso_rules.yaml 또는 UI 규칙설정(PII 유형 표)에서 조정할 수 있습니다.

판정 신호 (5종 + 전파) — 최종 등급은 아래 신호들 중 가장 민감한 등급으로 융합됩니다(보수적 max). 각 신호는 등급을 올릴 수만 있고 함부로 내리지 않습니다. 어느 신호로도 못 정하면 보류(none) → 검토 대상.

신호무엇을 보나비고
rule (내용)PII 유형(위 표) + 기밀사전 키워드. 결합식별성(combo) 포함본문 텍스트 기반
sensitive (민감정보) 2026-08-15 신규법상 민감정보(건강·유전·성생활·사상/정치·노조·범죄경력·인종) 키워드 → C일반 키워드와 분리된 독립 신호(정책·감사 명확)
stamp (보안분류 표식) 2026-08-15 신규문서에 찍힌 "대외비·기밀·관계자 외 열람금지" → C, "내부용" → S머리·반복일 때만 인정(오탐↓)
path (경로)파일이 놓인 폴더/서버(예: /인사/, //hr-server/)텍스트 안 엶
name (파일명)파일 이름 속 키워드(예: 대외비_보고서.hwp)참고용(seed 불가)
embed (임베딩 전파)보류 문서를 seed와 유사도로 구제(2차 패스)--propagate 참고

결합식별성(combo) 2026-08-15 신규 — 개별론 낮아도 여러 PII가 한 문서에 모이면(개인정보보호법·GDPR '결합용이성') 상향됩니다. 예: 주민번호+계좌 → C, 주민번호+주소 → C, 전화·이메일·주소 중 2종+ → S. rule 신호의 layer:"COMBO" 히트로 표시됩니다.

스탬프(stamp)는 본문 한복판의 단발 언급("이 문서는 대외비가 아님")은 무시하고, 표식이 문서 머리(앞 400자)에 있거나 2회 이상 반복될 때만 인정해 오탐을 줄입니다("관계자 외 열람금지" 같은 명시 문구는 위치·반복 무관 1건도 인정). 머릿범위/반복횟수는 환경변수로 조정.

※ sensitive·stamp·combo의 정책(단어·범주·조합·등급)은 cso_rules.yaml의 sensitive/stamps/pii_combos 섹션에서 조정합니다.

📖 규칙셋 cso_rules.yaml의 모든 섹션·필드 의미는 별도 레퍼런스 문서 CSO_Rule.html(규칙셋 필드 레퍼런스)에서 표로 확인할 수 있습니다.

분류 방식 선택 (배타) — 기본은 규칙으로 등급을 내고, 필요할 때만 임베딩을 씁니다. 아래 두 옵션으로 한쪽만 쓰도록 강제할 수 있습니다(동시 지정 불가).

옵션동작임베딩seed
--rule-only규칙(내용·민감정보·스탬프·경로·파일명)만으로 분류. 벡터·전파 안 함안 함(가장 빠름)불필요
--vector-only규칙 검사 없이, 문서 벡터를 seed 와 비교(전파)해서만 등급 결정전량 임베딩필수 --seeds
:: 규칙만 — 가장 빠른 분류(임베딩 모델 불필요)
csoclassify.exe --dir "D:\collected" -r --rule-only --format jsonl --out result.jsonl

:: 벡터만 — 규칙 무시, seed 와의 임베딩 유사도로만 분류(비교 기준 seed 필수)
csoclassify.exe --dir "D:\collected" -r --vector-only --seeds "cso_seed.jsonl" --format jsonl --out result.jsonl

--vector-only 결과는 signals에 embed만 있고(규칙 신호 없음) decided_by:["embed"]로 나옵니다. seed 와의 유사도가 임계 미만이면 보류(none)가 됩니다. --vector-only인데 --seeds 파일이 없으면 인자 오류로 안내 후 종료합니다.

:: 규칙만으로 빠르게(임베딩 없음)
csoclassify.exe --dir "D:\collected" -r --format jsonl --out result.jsonl

:: 선택적 임베딩(보류·seed 후보만) — 보류 구제/승격에 쓸 벡터 확보 + 빠름 (권장)
csoclassify.exe --dir "D:\collected" -r --embed-needed --format jsonl --out result.jsonl

:: 특정 확장자 여러 개만 골라 처리 — --glob 에 콤마로 패턴 나열(중괄호 "*.{hwp,pdf}" 도 가능)
csoclassify.exe --dir "D:\collected" -r --glob "*.hwp,*.hwpx,*.doc,*.docx,*.pdf" --format jsonl --out result.jsonl

:: 문서 1개를 분류하면서, 보류면 seed 저장소로 전파까지 한 번에
csoclassify.exe --auto-propagate --seeds "cso_seed.jsonl" --file "문서.hwp"

:: 결과 jsonl 에 추출 텍스트도 함께 저장
csoclassify.exe --with-text --dir "D:\collected" -r --format jsonl --out result.jsonl

:: [프라이버시 주의] 검출된 원문 PII 값도 결과에 저장(기본 미포함)
csoclassify.exe --classify --with-pii --file "문서.hwp" --out result.json

--with-pii 를 주면 결과에 pii 필드가 추가됩니다(원문 값 — 취급 주의). 로그엔 [pii N detected] 로만 남습니다:

"pii": [
  { "label": "RRN",  "value": "900101-1234568",      "start": 7,  "end": 21 },
  { "label": "CARD", "value": "4539-5787-6362-1486", "start": 25, "end": 44 },
  { "label": "IP",   "value": "192.168.0.10",         "start": 70, "end": 82 }
]

출력 예시(--file, 기본 json) — 대외비 표지 + 진단서 + 주민번호·계좌가 함께 있는 문서:

{
  "file": "샘플.hwp",
  "grade": "C",
  "confidence": 0.95,
  "method": "fusion",
  "decided_by": [ "rule", "sensitive", "stamp" ],
  "seed_eligible": true,
  "signals": {
    "rule": { "grade": "C", "hits": [
      { "id": "rrn", "name": "주민등록번호", "layer": "L1", "count": 1, "grade": "S", "terms": [] },
      { "id": "bank_account", "name": "계좌번호", "layer": "L1", "count": 1, "grade": "S", "terms": [] },
      // combo: 개별 S 인 주민번호+계좌가 결합 → C 로 상향
      { "id": "identity_financial", "name": "신원+금융 결합(재식별·금융피해)",
        "layer": "COMBO", "count": 2, "grade": "C",
        "terms": [ { "term": "ACCOUNT", "count": 1 }, { "term": "RRN", "count": 1 } ] }
    ] },
    "sensitive": { "grade": "C", "hits": [
      { "id": "health", "name": "건강정보", "category": "건강", "grade": "C", "count": 2,
        "terms": [ { "term": "진단서", "count": 1 }, { "term": "투약내역", "count": 1 } ] }
    ] },
    "stamp": { "grade": "C", "hits": [
      { "id": "stamp_confidential", "name": "대외비/기밀 스탬프", "grade": "C",
        "mode": "head", "count": 1, "term": "대외비" }
    ] },
    "path": { "grade": null, "source": null },
    "name": { "grade": null, "hits": [] }
  },
  "rule_version": "cso-2026.08.3",
  "ts": "2026-08-15T14:20:39+09:00"
}

최종 등급은 여러 신호 중 가장 민감한 등급으로 융합됩니다(위 예는 rule·sensitive·stamp 가 모두 C). decided_by=최종 등급을 만든 신호들, method=fusion(신호가 등급을 냄) / unclassified(아무 신호도 못 내 보류). stamp 히트의 mode=head(머리) / repeat(반복) / always(명시문구) — 왜 스탬프로 인정됐는지.

C 기밀 S 민감 O 공개 · 어느 신호로도 못 정하면 보류(none) → 검토 대상.

기본 동작(분류)은 전파를 하지 않습니다. seed 저장소가 있어도 자동 전파는 안 하며, 보류 문서까지 seed 로 구제하려면 --auto-propagate를 함께 주세요(단일 문서 확인에도 유용). 대량 배치는 분류 후 --propagate 2차 패스로 처리해도 됩니다.

② 임베딩 벡터 — --embed

분류 없이 임베딩 벡터만 뽑습니다(파일·차원·벡터 JSON).

csoclassify.exe --embed --file "문서.docx"
csoclassify.exe --embed --dir "D:\docs" --glob "*.hwp" --format jsonl --out vec.jsonl

출력 예시(--embed --file, 기본 json):

{
  "file": "문서.docx",
  "model": "dragonkue/multilingual-e5-small-ko",
  "dim": 384,
  "chunks": 1,
  "vector": [ -0.0566, 0.0062, -0.0231, 0.0274, ... (384개) ],
  "elapsed_ms": { "extract": 41.0, "embed": 22.3, "total": 63.5 }
}

벡터를 공백구분 텍스트로 보려면 --format text(→ 파일명 <탭> 0.01 -0.02 …).

③ 추출 텍스트만 — --text-only

csoclassify.exe --text-only --file "문서.hwp"

출력 예시(추출·정제된 원문 텍스트):

===== 문서.hwp =====
2025년 인사발령 및 대외비 안내. 담당자 연락처 010-1234-5678. 주민등록번호 900101-1234568.

④ 라벨 전파 — --propagate (보류 구제, 2차 패스)

1차 결과(벡터 포함)의 보류 문서만 seed 와 유사도로 비교해 등급을 전파합니다. 모델이 필요 없습니다(벡터 연산만).

csoclassify.exe --propagate result.jsonl --seeds cso_seed.jsonl --format jsonl --out result.jsonl

출력: 갱신된 레코드가 --out 파일에 다시 저장되고, 처리 요약이 화면(stderr)에 나옵니다:

[propagate] seeds=128 already_graded=940 embed_decided=57 still_unclassified=12 no_vector=3

로그 파일에는 레코드마다 [전파결과][임베딩](임베딩이 등급을 정함) / [전파결과][통과(rule 확정)](이미 확정돼 그대로 통과) / [전파결과][보류(미확정)] 태그로 구분되어 남습니다. --seeds를 주면 외부 큐레이션 seed + 코퍼스 내부 seed를 합쳐 비교하고, 생략하면 내부 seed만 씁니다.

⑤ 데몬 제어

csoclassify.exe --status   :: 상주 데몬 상태(모델·유휴시간)
csoclassify.exe --stop     :: 상주 데몬 종료
csoclassify.exe --serve    :: 데몬으로 직접 기동(보통 자동)

분류 (C/S/O)

인자값설명
(기본)—모드 플래그가 없으면 C/S/O 분류가 기본. 레코드(json/jsonl) 출력 (예전 --classify 는 생략 가능 — 붙여도 무시)
--rule-only 2026-08-15—규칙(cso_rules.yaml)만으로 분류 — 임베딩·전파를 하지 않음(가장 빠름). --vector-only 와 배타
--vector-only 2026-08-15—규칙 검사 없이 임베딩 벡터를 seed 와 비교해서만 분류. --seeds 필수(비교 기준). --rule-only 와 배타
--embed—분류 대신 임베딩 벡터만 출력(파일·차원·벡터)
--rules경로규칙셋 경로 기본 exe 옆 cso_rules.yaml
--failsafe[등급] 값 생략 시 S어느 신호로도 못 정한 문서에 부여할 기본등급
--embed-needed—보류·seed_eligible 문서에만 임베딩(확정문서 생략 → 빠름). 권장
--with-vector—모든 문서에 임베딩(구 동작, RAG 등 전량 벡터 필요 시)
--propagatejsonl 경로1차 레코드의 보류 문서에 라벨 전파(모델 불필요)
--seeds경로전파 비교 기준 seed(cso_seed.jsonl). 없으면 내부 seed 사용
--auto-propagate—분류 직후 보류 문서를 seed 로 전파까지 한 번에(단일 문서 확인 포함). 보류 임베딩 자동 활성화 · --seeds 있으면 외부+내부, 없으면 내부 seed
--with-text—결과 레코드에 추출(정제) 텍스트를 text 필드로 함께 저장 기본 미포함(프라이버시)
--with-pii—[프라이버시 주의] 검출된 원문 PII 값(주민번호·카드번호 등 실제 값)을 pii 필드로 저장 기본 미포함. 로그엔 건수만([pii N detected]), 원문은 --out 파일에만

모델 · 임베딩

인자값설명
--model별칭 기본 e5-small-ko임베딩 모델. e5-small-ko(384d)·e5-small·ko-sroberta(768d)
--max-tokens정수 기본 512청크 1개의 최대 토큰 수(e5 모델 최대 시퀀스 길이)
--overlap정수 기본 32인접 청크가 겹치는 토큰 수
--normalize / --no-normalize— 기본 정규화 on출력 벡터 L2 정규화 여부
--precisionf32 | f16 기본 f32출력 벡터 정밀도
--per-chunk—문서 1벡터 대신 청크별 벡터 출력
--num-threads정수onnxruntime 스레드 수
청킹(chunking)이란? 긴 문서를 임베딩 모델이 한 번에 처리할 수 있는 크기로 잘라, 각 조각(청크)을 임베딩한 뒤 평균내어 문서 1개의 벡터를 만듭니다. 두 값으로 조절합니다:
  • --max-tokens — 청크 1개의 최대 토큰 수(기본 512, e5 모델의 최대 시퀀스 길이). 크게 하면 청크 수↓·문맥↑, 작게 하면 더 잘게 나뉨.
  • --overlap — 인접 청크가 겹치는 토큰 수(기본 32). 청크 경계에서 문맥이 끊기지 않도록 조금 겹칩니다.
:: 청크 크기·겹침을 직접 지정(생략하면 512 / 32)
csoclassify.exe --file "문서.hwp" --max-tokens 256 --overlap 32

로그

기본 로그는 <exe폴더>\log\csoclassify-YYYYMMDD.log(UTF-8)에 남습니다. 로그에는 실제 실행 커맨드라인과 파일별 결과 JSON(벡터는 [vec dim=384]로 축약)이 기록되어 재현·추적에 씁니다. --log 경로로 위치 변경, -v로 화면 출력·DEBUG.

모델 경로: onedir 배포는 <exe폴더>\models\e5-small-ko\를 그대로 읽습니다(캐시·해제 없음). 압축(.tar.xz)으로 배포한 경우에만 최초 1회 %LOCALAPPDATA%\CSOClassify\models\<모델>에 풀어 재사용합니다.

7 자주 쓰는 예시

:: 1) 수집 폴더 전체 분류 → 결과 파일 (진행상황 표시)
csoclassify.exe --dir "D:\collected" -r --embed-needed ^
    --format jsonl --out "D:\collected\result.jsonl" --progress

:: 2) 문서 1개 등급만 빠르게 확인
csoclassify.exe --file "D:\docs\계약서.hwp"

:: 3) 보류 문서 구제(전파) — seed 저장소와 비교
csoclassify.exe --propagate "D:\collected\result.jsonl" ^
    --seeds "cso_seed.jsonl" --format jsonl --out "D:\collected\result.jsonl"

:: 4) 미검출 문서에 기본등급 S 부여(보수적)
csoclassify.exe --dir "D:\collected" -r --failsafe S --format jsonl --out result.jsonl

:: 5) 데몬 상태 확인 / 종료
csoclassify.exe --status
csoclassify.exe --stop

:: 6) 청킹 조절 — 긴 문서는 청크를 크게(문맥↑), 짧은 문서 위주면 작게(세밀)
csoclassify.exe --dir "D:\collected" -r --embed-needed ^
    --max-tokens 512 --overlap 64 --format jsonl --out result.jsonl

:: 7) 문서 1개를 작은 청크로 세밀하게 임베딩(기본 512/32 → 256/32)
csoclassify.exe --embed --file "긴문서.hwp" --max-tokens 256 --overlap 32

※ 위 ^는 Windows cmd에서 줄바꿈 이음 문자입니다(한 줄로 써도 됨).

8 주의사항

  • 더블클릭 금지 — 명령줄 도구라 창만 깜빡입니다. 반드시 인자와 함께 실행.
  • 경로에 공백이 있으면 "큰따옴표"로 감싸세요.
  • --out은 절대경로 권장 — 상대경로는 실행 위치(작업폴더)에 따라 엉뚱한 곳에 저장될 수 있습니다.
  • 한글 파일명/출력은 UTF-8로 고정되어 깨지지 않습니다.
  • 첫 실행이 느린 것은 onedir 첫 기동과 모델을 메모리에 올리기 때문이며 정상입니다(이후 빠름).
  • 오프라인 동작 — 인터넷 없이 됩니다. 실행 오류 시 대상 PC에 Microsoft Visual C++ Redistributable x64 설치, 백신 예외 등록.
  • 도움말은 csoclassify.exe -h, 버전은 csoclassify.exe --version.
